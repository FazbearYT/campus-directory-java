# Campus Directory

Учебное JavaFX-приложение «Справочник контактов» для последовательного выполнения лабораторных работ по Java.

## Вариант

Цель каждой лабораторной — максимальный уровень. Уровни кумулятивны: выполняются все пункты минимума, среднего и максимума, а также общие требования задания. Готовность проверяется по каждому пункту ТЗ отдельно; успешные тесты не заменяют проверку полноты. Снижение целевого уровня требует явного решения владельца проекта.

Вариант 4: справочник контактов с последующим хранением данных в префиксном дереве.

## Требования

- JDK 21 или новее
- Gradle Wrapper

## Запуск

В PowerShell из корня проекта:

```powershell
.\gradlew.bat run
```

Запуск тестов:

```powershell
.\gradlew.bat test
```

Для проверки реального рендеринга JavaFX в настольной сессии:

```powershell
$env:CAMPUS_GUI_TESTS = "true"
.\gradlew.bat test --rerun-tasks
Remove-Item Env:CAMPUS_GUI_TESTS
```

Без этой переменной GUI-тесты пропускаются, чтобы обычный набор мог работать без графического окружения.

Глобальная установка Gradle не нужна: требуемая версия загружается Wrapper при первом запуске.

`SynchronizedTrie<Contact>` получает `Contact::getName` и `Contact[]::new`: первая функция извлекает ключ, вторая создаёт массив нужного типа. Само ядро не зависит от модели контакта. Ключ должен оставаться неизменным, пока значение находится в дереве; ключ ограничен 256 символами до приведения регистра. Для массивов параметризованных узлов используются два локальных проверяемых по устройству структуры приведения типов: массивы закрыты внутри ядра и содержат только узлы одного `T`.

Рабочий `SynchronizedTrie<T>` синхронизирует каждую публичную операцию на одном мониторе и скрывает ядро. `TrieStorage<T>` без синхронизации доступен только внутри пакета и используется напрямую лишь экспериментом. Чтение между двумя отдельными вызовами может увидеть изменения другого потока: последовательность вызовов не является транзакцией.

В эксперименте гонки общий сигнал старта выпускает восемь писателей. После завершения проверяются `size`, счётчик корневого поддерева, число элементов обхода и нахождение каждой ожидаемой записи; ошибки операций выводятся явно. Небезопасный запуск может случайно завершиться без расхождений — интерфейс сообщает об этом и предлагает повторить опыт. Защищённый запуск обязан сохранить все 16000 значений. Оба набора изолированы от рабочего справочника. Результаты без защиты нельзя интерпретировать как корректные замеры производительности.

`TreeMap` выбран как ближайший стандартный упорядоченный индекс по строковым ключам. Сравнение проводится на одинаковых наборах с уникальными именами: вставка, точный поиск, удаление, сбор массива по префиксу и подсчёт совпадений. Поиск префикса в TreeMap использует `tailMap` и останавливается на первой неподходящей строке. Подсчёт требует обхода совпадений, в отличие от поддерживаемого счётчика Trie. Trie измеряется с синхронизацией, TreeMap — без неё; сравнение отражает эти реализации, а не изолированную стоимость алгоритма. Дубликаты проверяются отдельными тестами Trie и не входят в этот эксперимент. Готовый индекс не применяется для данных справочника.

- собственное префиксное дерево на узлах и динамических массивах без коллекций как основного хранилища;
- вставка, точный поиск и удаление с очисткой пустых ветвей;
- несколько контактов с одинаковым именем;
- регистронезависимое автодополнение и подсчёт контактов по префиксу;

- генерация до 100 000 контактов в фоне с прогрессом и отменой;

Выбранная сортировка таблицы сохраняется при обновлении и поиске. Одинаковые контакты выбираются по конкретному экземпляру. Во время фоновой операции закрытие окна блокируется: дождитесь её завершения или воспользуйтесь отменой; сохранение CSV необходимо дождаться.

Enter в поле поиска запускает автодополнение: таблица показывает все имена с введённым префиксом. «Найти точно» показывает первый контакт с полным совпадением нормализованного имени; при отсутствии совпадения таблица пуста. «Показать все» возвращает весь набор. CSV-диалог сначала открывает `samples`, затем запоминает выбранную папку до завершения приложения; если она недоступна, снова выбирается папка примеров либо рабочая папка.

Телефон содержит от 3 до 25 символов и минимум 3 цифры; допускаются пробелы, скобки, дефисы и один `+` в начале. Генератор использует одинаковый формат цифр независимо от региональных настроек системы. На окнах шире 2048 пикселей изображение дерева масштабируется из ограниченной текстуры, поэтому края не обрезаются.

Перед генерацией или импортом поверх непустого набора запрашивается подтверждение замены. Полностью повреждённый CSV не заменяет текущие данные. Отмена чтения или построения, в том числе на последнем уведомлении о прогрессе, сохраняет предыдущий набор.

Замеры включают два прогревочных и пять измеряемых прогонов на свежих деревьях; отображается медиана среднего времени одного вызова в микросекундах. Основные операции выполняются `N` раз, дополнительные — 100 раз по разным двухсимвольным префиксам. Число вызовов явно указано в окне результатов. Это учебный эксперимент: значения зависят от JIT, GC, нагрузки и количества совпадений; они не заменяют полноценный микробенчмарк.

Сохранены возможности лабораторной работы №1:

- редактирование только типов, реализующих `Editable`;
- добавление личных и корпоративных контактов;
- загрузка и сохранение UTF-8 CSV;
- экранирование разделителя и кавычек в CSV;
- пропуск повреждённых строк с указанием номера и кода ошибки;
- проверка имени, телефона, e-mail и корпоративных полей;
- безопасная замена сохраняемого файла через временный файл;
- модульные тесты модели, CSV и сервисного слоя.

## Формат CSV

```text
type;name;phone;email;organization;position;extension
```

Допустимые значения `type`: `PERSONAL`, `CORPORATE`, `EMERGENCY`. Поля `position` и `extension` заполняются только у корпоративного контакта. Аварийные контакты доступны только для чтения и появляются через импорт.

Запись занимает одну физическую строку. Имя ограничено 256 символами; перевод строки и табуляция в телефоне запрещены. После закрывающей кавычки CSV допускается только разделитель или конец строки.

Готовый набор данных находится в `samples/contacts.csv`. Файл `samples/contacts-with-errors.csv` демонстрирует пропуск некорректных строк.

## Асимптотика Trie

`m` — длина нормализованного имени или префикса, `b` — максимальное число детей одного узла, `s` — число узлов и контактов найденного поддерева, `k` — число контактов с одинаковым нормализованным именем. Трасса хранится как номер последнего посещения в каждом узле и не копирует строки префиксов.

| Операция | Сложность | Причина |
|---|---:|---|
| Точный поиск | `O(m log b)` | Дети узла хранятся в отсортированном собственном массиве, используется двоичный поиск. |
| Вставка | Амортизированно `O(m · b)`, отдельное расширение дубликатов `O(k)` | При создании ребёнка элементы массива могут сдвигаться; массив контактов иногда расширяется. |
| Удаление | `O(m · b + k)` в худшем случае | После поиска выбирается контакт среди дубликатов; пустые ветви удаляются со сдвигом массива детей. |
| Автодополнение | `O(m log b + s)` | Сначала находится префикс, затем обходится его поддерево. |
| Подсчёт по префиксу | `O(m log b)` | Число контактов заранее поддерживается в каждом узле. |

Вставка в массив контактов амортизированно `O(1)`, отдельное расширение массива дубликатов стоит `O(k)`. Для `b = 0` или `1` стоимость шага поиска постоянна. Построение снимка — отдельная операция: для `v` показанных узлов и глубины `d` она требует `O(v · d)` времени и памяти из-за строк путей. Снимок строится очередью и собирается снизу вверх; основной Trie не копируется в готовые коллекции.

В оценке удаления сравнение полей контакта считается постоянным; если учитывать длину строк полей `L`, слагаемое поиска среди дубликатов становится `O(k · L)`.

## Проверки устойчивости

Регрессионные тесты проверяют строгие кавычки CSV, сохранность файла при ошибке записи, roundtrip 1200 случайных записей с кавычками/разделителями/Unicode, границы длины имени, расширение Unicode при приведении к нижнему регистру, отмену на последнем шаге, 50 000 случайных операций против эталонной модели и конкурентную вставку/поиск/удаление 16 000 контактов. Настольные тесты отдельно проверяют реальную отрисовку и прокрутку широкого и глубокого дерева.

Дополнительно проверяются независимость генератора от локали, формат телефона и e-mail, повреждённый UTF-8, очистка временного файла после неудачной записи, атомарность импорта с ошибкой в середине, сохранение сортировки таблицы, выбор дубликатов, запрет закрытия при фоновой операции и покрытие широкого окна изображением дерева.

## Структура исходного кода

```text
model    — сущности, типы контактов, Editable и валидация
io       — чтение, проверка и атомарная запись CSV
service  — правила добавления, изменения и импорта
ui       — диалог добавления и редактирования
trie     — собственная структура, снимок узлов и трасса обхода
```
